# Following activity

Home shows the latest three updates below Recent Results in the same accordion as the other Home sections. Following starts expanded and can be collapsed by tapping its header; the update count badge remains visible in either state. A `3+` badge means more updates exist beyond the three-card preview, rather than claiming three is the full feed total. Unknown counts during initial loading or an initial error are omitted. View all inside the expanded section links to `/following`. Toggling only changes local display state and adds no provider requests. The full feed has All, Players, Matches and Tournaments filters, pull to refresh and cursor pagination. The navigation menu and notification inbox also link to it.

Home ranking updates have a SAPA/FIP switch. For you limits updates to followed players; Tour shows changes across players. SAPA uses verified nonzero national rank movement and shows points as totals, never as invented deltas. Local updates sort by the size of the rank movement, then current rank. FIP requires a nonzero rank or points change. Unchanged or unknown movement is excluded, with an explicit empty state when no changes are available. Latest international results are hidden on Home and remain available elsewhere.

Match score panels show portraits and country flags for each player when the provider or approved local directory supplies them. Exact IDs resolve international media; ambiguous local names keep initials. Public nationalities are normalized to country codes, with unrecognized values omitted. Entry cards show the tournament artwork and start date. Registration updates use the current calendar deadline for a live countdown, switching to Entries closed after the deadline. Countdown ticks stop in the background and only update the timer component.

Match schedule cards say **Upcoming match** when a time or court is first assigned after the source baseline. Later changes to known values say **Match time changed**, **Court changed**, or **Match time and court changed**. Cards include the scheduled date/time in SAST and the court when available; an unknown time stays **Time to be confirmed**. Missing/redacted fields, equivalent timestamp formats, unchanged snapshots and already-past start times do not create schedule updates. These cards do not imply that a previous match has finished or that play has started. Existing generic cards use Upcoming match because their previous schedule was not retained. Titles and details come from the shared backend; the dynamic app header ships in the next native build.

`following_activity` stores public facts once. Authenticated `get_following_feed` filters them against the caller's current local/pro player follows, starred matches and tournament subscriptions. Private or hidden events, unpublished draws, payment messages and contact details are excluded. Both shared tables deny direct client access; only the scoped read RPC is granted to authenticated clients. RLS without a permissive table policy is intentional.

Database triggers record confirmed paid/comped entries, published native results, profile bio/photo edits and SAPA ranking updates. Bio/photo and ranking edits group by player and UTC day. Americano uses published rally points and allows draws. Tournament detail alerts track start/end dates, venue/city, registration closing dates and confirmed early bird deadlines. Sponsor/name, fee, registration opening and planned draw release edits are silent. Historical posts hide cosmetic-only edits and strip cosmetic fields from mixed updates. The existing tournament notification jobs supply registration and early bird closing reminders 24 hours before their confirmed deadlines. Early bird copy names its own deadline and never shows the registration countdown. Actual draw publication, schedule publication, cancellation and final results also create activity. Feed records are independent of push preferences and never enqueue historical notifications.

Publishing a tournament schedule creates one feed post for the published revision, regardless of its match count. Draft edits and automatic match progression do not create publication alerts. Followers receive schedule/draw alerts through the existing job queue; participants keep their existing division draw and personal match alerts without an extra tournament schedule push. Delivery rechecks follows, notification preferences, public visibility, the published revision and current draw status. Private/archived/superseded publications cannot send stale alerts. These shared database rules apply to app and website callers immediately, with no new client build or Padel API requests.

## Padel API quota protection

`padel-api.ts` re-exports the shared governor used by app, website, scheduled snapshots and Following. Live and point feeds share a two-minute expiry; player metadata lasts 24 hours and completed matches seven days. One database lease and request budget apply across edge isolates. Expired responses retain their original timestamp and an explicit saved-data marker. Following collection and match-start alerts reject stale responses. API credentials never enter cache keys or public payloads.

Provider 429 responses persist Retry-After across callers. New upstream requests also stop at the internal minute, daily and monthly caps. Local history and tournament push delivery continue. Retry-After is a retry time, not a complete quota reset. See [the shared quota strategy](padel-api-quota.md) for budgets, refresh intervals and coverage limits.
