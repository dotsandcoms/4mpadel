# Entry price changes and native management

Both the event countdown Manage Entry button and the lower Manage partners / entry details button now open the native entry sheet. The fallback in the registration payment screen returns to the native event page. Existing registrations do not see a misleading private-event access-code prompt just to manage their entry.

The event page loads authoritative per-player balances through `native-entry-balance`. The sheet shows allocated entry credit, current price and outstanding amount. It displays “outstanding” instead of “Paid & Confirmed” when the current fee exceeds recorded entry credit. Unknown historical payment allocations are shown as unverified and cannot be charged again through this adjustment flow. The persisted legacy payment_status is not blindly changed to pending, which would make the original checkout charge the full fee again.

Successful original payment metadata (`covers` and `division_entry_fees`) determines entry credit, excluding partner fees, licences and management fees. Duplicate original checkouts are not summed as extra credit. Verified native balance payments are additional credit. Early-bird expiry by itself does not revoke an identifiable early-bird rate. Lowering the price does not create a negative amount or issue an automatic refund.

The new native `/events/pay-balance` screen reviews and pays only the remaining balance through the in-app Paystack browser. The backend authenticates the account, resolves the entry and price, stores an idempotent pending payment, and verifies the provider reference, amount, payer, currency, live mode and entry metadata before recording successful credit. The public return handler only redirects to the fixed native route. Pending attempts survive app restarts, and repeated confirmation cannot multiply credit. Existing paid entries can settle adjustments after registration closes; this does not reopen registration or allow new entries.

Balance adjustments are saved as `payments.metadata.source = native_entry_balance`. The mobile copy of paystack-refund includes verified adjustments in withdrawal refunds alongside the original entry fee, capped by each payment's remaining refundable amount. The copied service otherwise retains the existing authorization, deadline and refund rules. Division switches must settle a known existing entry balance first. No SQL migration is needed.

### Home pending actions
Home and the Notifications sheet now check authenticated entry balances for paid registrations, once per event (at most three concurrent requests). A verified positive balance creates a per-registration action showing the tournament, division, paid amount and amount due, opening `/events/pay-balance` natively. Original unpaid registrations retain their original payment route. Fully settled balances disappear on the next focus/foreground/pull-to-refresh load. Outstanding balances remain actionable after the tournament starts. Failed balance reads offer a retry action rather than silently hiding the check.

Home schedule/spotlight actions use entry management for balances, and companion schedule status no longer labels those entries paid. These client changes require a new installed app build after build 12; no database migration or server deployment is needed.
