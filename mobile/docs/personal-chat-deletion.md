# Personal chat deletion

The inbox options and conversation options offer **Delete conversation** for direct and group chats, with native confirmation. Deleting clears the current user's history and local draft and returns to the inbox. It does not leave a group, block a player, remove another participant's messages, or remove moderation evidence. A later visible message restores the inbox row; earlier messages and quoted previews remain hidden for the deleting user. Official event channels retain their existing membership controls.

Migration `20261112102049_messaging_delete_conversation.sql` adds a nullable personal sequence boundary to the existing private `messaging.members` table. The checked RPC derives its owner from the existing verified-session actor and requires active membership. It uses the same account/conversation locks as sending. The common visibility check applies the boundary to history, pagination, previews, quotes, badges and queued delivery context. The list filters before its limit. Old clients cannot recreate an unread reminder for an otherwise empty deleted chat.

The public wrapper uses security invoker. Only authenticated clients can execute it and its checked private entry point; helper functions and private tables remain inaccessible. No public tables or sequences are created, so the existing table access contracts remain unchanged. Root and mobile migrations were reviewed together; no historical migrations were replayed.
