# New Admin commit audit — Money and Network

The original New Admin baseline `999fb2f9e2cb6f1c27c60a18ec445114bcd7d513` is the merge base and ancestor of pinned main `f17c90b655f522e7188c81c85f1195c048427b03`. The range contains **103 reachable commits**, including parallel versions and merges. Compared parity branch `d883e8f7c20e0721d82e51f5e0c806ebc0caf5f9`, which has `f17c90b6` as an ancestor and includes the original Club operations. Named native Paystack reconciliation was additionally verified in the isolated follow-up described below.

The audit screened each commit's first-parent changed files, reviewed direct diffs for relevant web, backend and native compatibility changes, and checked the tip implementation and available tests. A merge row compares the merge to its first parent, then attributes already inspected behavior to the originating rows. Coverage below is source and synthetic-test evidence. It does not establish which migrations are hosted or whether a provider accepted a real payment, payout, email or authenticator action.

- **Covered** means New Admin reaches the operational behavior or uses the corresponding current authoritative backend.
- **Gap** means some relevant behavior is missing, less complete, or lacks a verified permission path.
- **Other** means a consumer/UI-only change or a duplicate or superseded change that introduces no separate New Admin control.

The audited range does not introduce a separate new website Club/Organisation/Federation manager. - Direct club owners and admins can manage staff/admin members in their selected club. This uses live membership checks and exact-email player lookup within the account’s existing player visibility. Existing owner changes and membership notices remain available from the platform workspace. Organisation membership actions remain in the platform workspace as in current Admin.

- Club approval's claim and membership/publication mutations are separate existing RLS-protected API calls. Partial progress is surfaced, applicant mail suppressed when incomplete. Pending invitation duplicates are prevented within available RLS history and exact retry ID; there is no cross-admin uniqueness guarantee.

## Reviewed Paystack recovery

Commit `6bf38406` adds single and page review for a platform super admin. The Edge function verifies the exact reference, live status, amount, currency and refund state. The database rechecks the reviewed target and records the receipt and audit together. A retry returns the recorded outcome. Exact existing event entries, approved licence bundles and saved standalone licence purchases can be matched. An authorised decision can record otherwise unsupported receipts as unallocated funds while preserving existing player, entry and licence state.

Synthetic Chromium exercised single/page review and rejected missing platform authority. `tests/adminPaystackBackfill.sql` passed with the protected checkout fixtures on PostgreSQL 17. The hosted recovery migration and Edge Function v1 are installed. The live permission check confirmed that regular signed-in clients and anonymous users cannot execute the database writer.
